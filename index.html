04 — How I work

What working with me looks like.

  1. Start with the problem

    Tell me what needs to change and why. I'll work out a path, raise risks early, and keep you close to the decisions as the work moves toward production.

  2. Remote, async, and international

    I've worked remotely across Bangladesh, the Netherlands, and Canada. I default to written updates and make time for calls when a conversation will move the work forward.

  3. Match the explanation to the audience

    Engineers need the trade-offs; stakeholders need the impact, timing, and constraints. I try to make both versions clear without changing the underlying decision.

  4. Measure before changing things

    I prefer logs, profiles, and real usage to a confident guess. The aim is the smallest change that solves the actual problem and is safe to keep.
